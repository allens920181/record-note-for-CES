# 神學院錄音筆記軟體 — 需求規格 v1.0

> 狀態：**五個階段全部完成。** 以下已是實作後的規格，與程式一致。

---

## 0. 一句話定位

給神學院學生的課堂工具：**錄音 → 逐字稿 → 雙欄筆記 → 整學期知識庫**。
資料存在自己的電腦，轉錄用自己的 API key，不經過任何第三方伺服器。
**摘要與整理由你自己做**，軟體不代勞。

## 3. STT 方案決定：Groq 上的 Whisper large-v3

### 3.1 「只要用 Whisper 就好嗎？」— 是，但要挑對託管商與變體

**用 Whisper 的三個理由：**

1. **`prompt` 參數可餵詞彙表。** 這是決定性的。你的課有希臘文／希伯來文術語和神學家人名，通用模型必錯。Whisper 的 API 讓你把詞彙表塞進 `prompt`，直接拉高這些詞的命中率。
2. **中文表現穩定**，large-v3 是目前開源多語模型裡最可靠的一梯。
3. **你不需要講者分離**（已確認手動設定講者名稱），所以 Deepgram 最大的賣點對你沒有價值 → 直接排除，省一半錢。

### 3.2 為什麼是 Groq 而不是 OpenAI

同一個 Whisper 模型，Groq 便宜 3.2 倍（$0.111 vs $0.36），而且跑在 LPU 上，一小時音訊約 15 秒轉完。

**Groq 免費層對你的用量幾乎剛好夠：**

| 限制 | 額度 | 你的用量 |
|---|---|---|
| 每日音訊 | 28,800 秒（8 小時） | 平均 3 小時／天 ✅ |
| 每小時音訊 | 7,200 秒（2 小時） | 一堂 3 小時的課需約 1.5 小時處理 ⚠️ |
| 每日請求 | 2,000 次 | 遠遠夠用 ✅ |
| 每分鐘請求 | 20 次 | 需要節流 ⚠️ |

→ **設計對策：轉錄工作以佇列處理，顯示進度，可掛著跑。** 不追求即時。
→ 提供「付費加速」開關：超過免費額度時自動改走付費，或手動切換。

### 3.3 為什麼是 large-v3 而不是 turbo

turbo 是 large-v3 的剪枝微調版：解碼層從 32 降到 4，參數從 1.54B 降到 809M。速度快很多，代價是品質下降——而且**退化集中在非英語**，粵語、泰語等尤其明顯。

你的場景正是它最會出錯的地方：中文授課 ＋ 外語術語。

而且**在免費層底下，兩個模型的額度完全相同**（20 RPM / 2,000 RPD / 7,200 音訊秒每小時 / 28,800 每日）。既然免費層不用多付錢，就直接用準確度高的那個。就算超額付費，一學期也只差 $22。

### 3.4 備援設計

Groq 用的是 **OpenAI 相容端點**，所以「Groq」與「OpenAI」在程式裡是同一條路徑，只差 base URL 和 key。

→ 設定頁預設 Groq，保留 OpenAI 作為第二來源。某段轉壞或 Groq 出狀況時可一鍵改用另一家重試該段。這在架構上幾乎零成本。

### 3.5 待驗證

- **CORS。** Groq 與 OpenAI 是否允許瀏覽器直接呼叫，尚未實測（開發沙盒的網路政策擋住了這些網域）。**這是開工前第一件要在 Chrome devtools 上驗的事。** 若不支援，備案是加一層 Cloudflare Worker proxy。
- **免費層資料條款。** 課堂錄音上傳免費層前，值得確認 Groq 對免費層資料的使用政策，以及學校對課程錄音的規定。
- 費率與免費層額度可能變動，以官網現價為準。

## 5. 功能規格

### 5.1 錄音與轉錄

- **上傳**：mp3 / m4a / wav / webm / mp4，拖放即可
- **內建錄音**：每 3–5 分鐘落一塊到本機資料夾、Wake Lock 防休眠、暫停續錄、即時波形計時
- **轉錄管線**：壓成 opus 32 kbps mono → 依靜音點切片（每片 &lt; 25 MB）→ 佇列送 Groq（節流至 20 RPM 內）→ 時間戳偏移校正 → 拼接
- **韌性**：每片獨立進度，單片失敗可重試或改用備援 provider，不必整份重來
- **額度守門**：設定頁有滾動視窗的用量儀表板（每日 8 小時／每小時 2 小時），
  轉錄前如果這份錄音會超過今天剩下的量，會先問過你才送出
- **匯入現成逐字稿**：srt / vtt / txt

### 5.2 專有名詞表 — 這個場景的關鍵功能

中文授課夾雜希臘文／希伯來文術語，通用 STT 必錯。透過 Whisper 的 `prompt` 參數餵詞彙表可大幅改善。

- **兩層**：全域詞彙（隨每一門課的轉錄送出）＋ 每門課自己的詞彙。
  轉錄時兩者合併去重，所以同一個詞不必兩邊都放
- **詞彙表總表**（`/glossary`）：所有課程的詞在同一頁，可依學期篩選、依詞或課名搜尋。
  一個詞看得到它用在哪幾門課；出現在兩門以上的會被挑出來建議升成全域。
  改名會一次改掉所有課程與修正紀錄裡的那個詞——自動學到的詞若拼錯，
  這是唯一不必開七個課程頁去修的地方
- 每門課的詞彙表也可在課程頁手動維護（**一個詞一顆**，按 Enter 或頓號成為一顆、
  點 × 移除），或在逐字稿選取文字直接加入。
  原本是一個以頓號分隔的文字框，而下方的修正面板一學到新詞就會把整個輸入框重建——
  你正在打的字會直接消失。清單是資料、輸入框只裝下一個詞，兩者才不會互相覆蓋
- **從修正紀錄累積，但分兩種處理**——這是實作後修改過的設計：

  | 修正 | 做法 | 為什麼 |
  |---|---|---|
  | 拉丁字母（`chesid → chesed`、`Barht → Barth`） | 取整個詞，**同樣的修正出現第二次**時自動加入 | 編輯落在詞內，詞界由字母邊界決定，沒有猜的成分。要求兩次是避免打錯字被當成術語 |
  | 中文（`加爾聞 → 加爾文`） | 列出涵蓋改動處的 2–5 字候選，**由你點一下決定** | 差異只有單一個字「文」，本身不成詞，而中文沒有詞界可循 |

  試過用虛詞當邊界來切詞，在最需要的詞上失敗：「經」在「已經」是虛詞、
  在「釋經學」是詞素；「來」在「後來」與「士來馬赫」同理。
  猜錯的詞會被送進 `prompt`，等於教模型寫錯字，比不猜更糟，所以改成輔助而非自動。

- 只改標點或空白不算修正，不會留下紀錄
- 內建一份神學基礎詞庫作為起點（神學家人名、宗派術語、常見原文音譯）

### 5.3 雙欄：逐字稿 ↔ 我的筆記

| 左欄：逐字稿 | 右欄：我的筆記 |
|---|---|
| 帶時間戳，跟著音檔捲動 | Markdown 編輯器 |
| 可直接編輯修正錯字（回饋進詞彙表） | 可插入時間戳連結 |
| 可 highlight 標記 | 可引用左欄選取段落 |
| 可標示講者（用課程層設定的名稱） | 可連到 PDF 頁碼 |

**核心價值：筆記裡的時間戳點下去，音檔直接跳到那一秒。**
上課按快捷鍵記一筆「這裡沒聽懂」，回家點一下就回到那個瞬間。

**軟體不提供任何 AI 文字整理功能。** 摘要、大綱、重點、複習問題都由你自己在右欄寫——那正是讀神學的功課本身。軟體的職責是讓你「找得到、跳得回去、寫得順」。

### 5.3b 筆記區

筆記是這個 app 的產出，其餘一切都是為了讓它寫得順、找得到、跳得回去。

- **儲存格式仍然是 markdown**，不做 block 模型。匯出、搜尋、備份全都建立在
  「筆記就是一份 markdown 文字」這件事上；換成 block 會把這三件事一起弄壞，
  換來的只是拖曳重排
- **`/` 指令選單**：標題、清單、待辦、引用、分隔線、三種標記、插入時間戳、引用逐字稿。
  可用中文篩選。markdown 的符號不該是學生需要記得的知識，
  而中文輸入法下為了打兩個 `*` 切換輸入法，是會讓人放棄使用格式的摩擦
- **選取即浮出的工具列**：粗體、斜體、底線、刪除線、行內代碼、字色、螢光筆、三種標記。
  分工是「工具列管字，`/` 選單管段落」——工具列作用在選取的字上，
  標題與清單作用在整行，混在一起會讓工具列寬過它所浮動的欄位
- **底線與顏色**：markdown 沒有這兩種語法，所以寫成每個 renderer 都認得的 inline HTML。
  儲存的是 hex（離開這個 app 仍然有意義），但編輯器內把已知色票對映回配色 token，
  所以那五個顏色就是這一頁其他地方在用的五個顏色，而不是五個很接近的別的顏色
- 鍵盤：`Ctrl+B/I/U`、`Ctrl+Shift+X`（刪除線）、`Ctrl+1~3`、`Alt+↑↓`（搬動整段）、
  `Alt+T`（時間戳）。快捷鍵印在 `/` 選單裡每個指令旁邊，並依平台顯示 `⌘⌥` 或 `Ctrl/Alt`
- **即時樣式**：標題、粗體、斜體、行內代碼、引用、清單、待辦框、標記色塊
  都在編輯器裡直接畫出來。**游標所在的那一行例外**——那一行把符號顯示出來，
  因為你正在改的就是它
- **標記**：`> [!重點]` / `> [!疑問]` / `> [!考點]`，Obsidian callout 語法。
  不另存欄位，因為只存在這個 app 裡的標記，匯出到 vault 就消失了——
  而 vault 正是這些筆記要去的地方
- **引用逐字稿**：選取 → 成為引用，時間戳取自**那個段落自己的 start**。
  用 `currentTime` 會在「捲回去找一句話但音檔還在播」時標上毫不相干的時間
- **大綱**：標題與標記組成跳轉清單。標記進大綱是因為標記的用途就是回來看
- **跨週彙整標記**：搜尋頁可以列出整學期所有的疑問／重點／考點。
  這是標記存在的理由——寫下它的那一週不是你需要它的時候
- **同一個編輯器用在每個長文字欄位**：課堂要求、作業的要求與備註、讀書筆記。
  這些地方本來是純 `<textarea>`，寫下的東西卻和筆記是同一種——
  一段要讀得懂的文字。分成兩套輸入方式，就是要求讀者記得「哪裡能打 `/`」
- **指令自己決定要不要出現**：每個指令都帶一個 `enabled`，
  所以沒有音檔的欄位不會列出時間戳，沒有地方收檔案的欄位不會列出「檔案」——
  列出一個按了沒反應的指令，比不列更糟
- **逐字稿的修正框不換**。那裡一格是一句話，內容不是 markdown

### 5.4 行事曆與自動開檔

**日曆是建立行程的主要方式。**一旦分組討論可能是不規則的，
用下拉選單填表就是錯的工具：看不到整週的形狀，也看不出衝堂。

| 視圖 | 用途 |
|---|---|
| **週曆** | 7 天 × 時間格。衝堂的項目並排顯示而非互相遮蓋。這是排課與看一週輕重的地方 |
| **月曆** | 一眼看完整學期的節奏與密度 |

**點空白處建立**：帶出課程、類型（正課／分組討論）、重複（每週／單次），
時間依點擊位置預填並對齊半小時。三種組合的行為不同：

- 每週 ＋ 會議 → 寫進課表並展開整學期
- 單次 ＋ 會議 → 只建立那一天的一個週次，不影響課表

其餘規則：

- 同一週的正課與分組討論共用同一個週次編號，列表依日期排序
- 週次編號以學期起始日往後每 7 天為一個窗口推算，刪掉或補開都能重算
- 點既有項目開出一張卡片：說明這是什麼，帶你去它住的地方，
  並且可以改時間、標記停課、從行事曆刪掉。
  每個行程都是一筆資料，所以改一筆就是改那一筆
- 一天塞不下時，月曆的「還有 N 項」按得下去，切到那一天的週曆
- 學期尚未開始時，日曆停在學期第一週而不是空白的今天
- 可標記停課、放假週

**同一個對話框。**上面這個「在某門課底下佔一段時間」的表單，
行事曆與課程頁用的是同一個元件、同一段建立邏輯。
課程頁進來時課程已經確定，就不再多問一次。

### 5.5 PDF 與課程檔案

- 上傳 syllabus、講義、閱讀材料，掛課程層或週次層
- 內建 PDF 檢視器（pdf.js）
- 抽出文字讓 PDF 可被跨週全文搜尋

### 5.5b 課堂要求與書目

大綱是一份 PDF，但「報告幾頁、引註什麼格式、遲交扣幾分」是**寫作業寫到一半**要查的，
為了一句話開一次 PDF 是純粹的摩擦。所以每門課多一塊：

- **一個文字框**。評分方式、出席規定、格式要求、遲交規則、考試範圍，全部抄進去。
  一開始做成 `{項目, 比重, 對應作業}` 的結構化表格，實際用起來是反的：
  要查的是一句話而不是一張表，而填了欄位的人之後還得再找地方把它讀回來。
  舊資料不會憑空消失——併成文字的一行
- **下方是書目上傳區**：教學大綱、指定書目、整學期共用的閱讀材料。
  PDF 會抽出文字供跨週搜尋；閱讀清單（§5.7）的每一本書也可以指到這裡的檔案，
  同一份掃描檔不必為了好幾週重傳

### 5.5c 每週學習進度

作業規劃（§5.6）算的是**這份作業還要幾小時**；這裡管的是**這一週要做什麼**。

- 每一週一張清單：課前讀完、課後整理筆記、複習上週逐字稿、報告再推一段。每項可填預估時數
- 和作業的子任務刻意分開：子任務是通往一份有截止日的成品的步驟；週進度是這一週本身。
  後者才是會悄悄落掉的東西，因為週四並沒有什麼東西到期
- 三個範本：一般週／報告週／考前週
- 指定閱讀可以一鍵拉進來，勾完會同時把那本書標成已讀完——兩邊不會各說各話
- 課程頁顯示整學期總計與每一週的進度。**沒排進度的週次不算落後**：
  「已排的 2 堂完成 4/8 項」是真話，「4/15」只是在說學期還沒過完

### 5.6 作業清單與規劃

- 清單 ＋ 截止日 ＋ 狀態 ＋ 關聯課程／週次，跨課程依截止日排序
- 子任務拆解，並可套用範本（期末報告 / 讀書報告 / 講道稿）
- 截止日出現在週曆與月曆上
- 可存常用的子任務範本（如「期末報告」五步驟），重複套用
- **步驟的預估時數加總成「還要幾小時」**，比單看死線更接近真實情況。

  每週固定的時段要**逐日數過去**而不是乘以概略週數——「還有三週」和「還有三個週日」
  在截止日落在週中時是不同的數字。單次挪出來的那幾天直接相加。

  拿這個數字對照子任務的預估時數，就能在還來得及的時候看出「差 11 小時」。

### 5.7 閱讀材料區

- 書目管理：書名、作者、章節、頁數範圍
- 對應到週次
- 進度追蹤：未讀 / 讀到第幾頁 / 已讀
- 讀書筆記，可與課堂筆記互相引用

### 5.8 整學期串聯

- **課程時間軸總覽**：一門課的所有週次攤開，主題、錄音狀態、筆記狀態一目了然
- **跨週全文搜尋**：一次搜尋逐字稿 ＋ 筆記 ＋ PDF 文字，結果顯示「第 8 週 01:23:45」，點下去直接跳到那句話。

  用**子字串比對**而非詞元索引：中文沒有空白，詞元切分會把整句當成一個詞，
  只有整句一模一樣才搜得到。而「搜你記得的那句話」本來就是這個功能的用途。
- **自己的筆記索引**：你在筆記裡下的標籤與標題，彙成一份可跳轉的全課大綱

串聯**完全是本地的導航與檢索**，沒有任何 AI 呼叫。整學期的複習素材由搜尋與你自己的筆記構成——
搜尋帶你回到原話，筆記是你的理解，兩者互為索引。

### 5.8b 側邊欄

導覽自己也是一個功能。原本五個連結和麵包屑擠在頂端同一行，
路徑一長就換行；而「回到上一門課的第 7 週」需要點三次。

- **一直在的課程樹**：五個功能頁在上，下面是學期選擇器與這學期的課程；
  課程展開就是週次。點課名進課程頁、點週次直接進工作區
- **只查已展開的課**：一學期五門課約七十個週次。
  預先撈起來，是把啟動時間賣給大概不會被打開的清單
- **標出你在哪裡**：目前的課程自己展開並標亮，目前的週次也是。
  週次頁的網址裡只有 sessionId，所以樹得先回頭問那一週屬於哪門課
- **窄視窗改成覆蓋**：`☰` 開關、記住選擇、點連結即收。
  寬視窗維持並排，且不因導航而關閉——那裡它是家具，不是彈出視窗。
  視窗寬度要持續監看：從寬拖到窄卻沒關閉，會留下一層吃掉所有點擊的遮罩
- 頂端因此只剩麵包屑

### 5.8c 課程頁的用語與密度

功能齊備之後，課程頁上是四個分頁、七張卡片，每張卡片頂著一段等長的灰字說明。
全部一樣重，等於沒有輕重；而分頁名稱是三個名詞用「·」串起來的清單。

- **一個分頁一個名字**：`上課週次` / `作業與閱讀` / `大綱與規定` / `課程設定`。
  三個名詞串在一起是打包清單，說不出它們為什麼在一起
- **需要三行免責聲明的名字就是錯的名字**：「作業時間」看起來像截止時間或
  「這份作業要花多久」，兩者都不是，所以卡片得花三行澄清。
  改叫**寫作業的時段**之後，那三行只剩空狀態需要
- **說明的用途是第一次遇到**：卡片空著才展開解釋，有內容之後縮成一行事實或消失。
  課堂要求也一樣——輸入框裡有字了，就不必再說明它為什麼是一個輸入框
- **空的卡片不出現**：沒有修正紀錄時整張卡不在；一堂課都還沒有時不顯示「學習進度」，
  因為下面的空狀態已經說了同一件事。兩個空狀態講同一件事，讀起來就是雜亂
- **一個動作在同一個畫面只出現一次**：工具列已經有「新增一堂課」，
  空狀態就不再擺第二顆；空狀態只留它獨有的出路（「去設定課表」在另一個分頁上）
- 相對地，**同一張畫面上的兩顆按鈕不能同名**：課表與寫作業時段各自的新增鈕
  一度都叫「新增時段」，改成「新增上課時段」與「新增寫作業時段」

接著把剩下的四個分頁各自收斂成一件事：

- **課表併進「編輯課程」對話框**。上課時間和名稱、老師、學分是同一種東西——
  設定一次、描述這門課是什麼；課程頁的標題列本來就把它印在學分旁邊。
  建立課程時一併問，省掉「建完再去另一個分頁排時間」這一趟。
  「依課表產生整學期」是動作不是欄位，留在「上課週次」
- **不該併進去的三個**：專有名詞表整學期都在長（且可從逐字稿直接加詞）、
  逐字稿修正是要逐筆處理的佇列、寫作業時段是你的行程而不是課的屬性。
  把持續在動的東西塞進「開了要關」的對話框，是把工作變成一趟趟出差
- **寫作業的時段搬去「作業與閱讀」**，和它服務的對象並列：
  作業卡片上的「到截止日為止排了 N 小時可以寫」，來源就在同一頁
- 於是「課程設定」這個模糊的名字消失，那個分頁改叫**詞彙表**——四個分頁各裝一件事

### 5.8d 課程頁：block 清單

課程頁的主體是**每一堂課一個 block**，其餘一切收進對話框。

- **整張卡是連結**。block 就是那一週的筆記，先找標題再點是多一步
- **block 之間可以插入筆記區**：分組討論、作業紀錄、其他筆記。
  插入點在兩張卡之間，而且**永遠在 DOM 裡**——只在 hover 時才存在的控制項按不到 tab，
  而這是把筆記歸到兩週之間的唯一辦法
- **位置真的照插入點走**：session 多一個可選的 `seq`。
  會議沒有這個欄位，退回它們的類型宣告順序（正課 0、分組討論 1），
  插在兩者之間就拿 0.5——落在放下去的地方，而且沒有東西要遷移
- **筆記區不是聚會**：沒有鐘點，也不進行事曆。把它畫在小時格上等於發明一個它沒有的時間
- **右邊三顆對話框**：編輯課程（課表＋專有名詞表＋逐字稿修正）、
  課程規定與作業（要求＋作業＋閱讀）、文件總覽

### 5.8e 檔案：三個入口，一份清單

檔案可以從課程層、週次層，或**筆記裡的 `/檔案`** 加進來。三者都是 `attachments`
的同一批資料列，所以「文件總覽」用一支查詢就列得完，並標出每份屬於哪一週。

- 筆記裡留下的是 `[📎 檔名](檔案路徑)` 而不是只有這個 app 認得的 id：
  匯出的 markdown 仍然指得到那份檔案
- **書目欄位拿掉了**——它只是課程層的檔案，卻另外長成一個區塊

### 5.8f 拿掉「寫作業的時段」

它是一段**不產生任何東西**的時間：不錄音、不開檔案、不留筆記。存在的唯一理由，
是替作業規劃算出「截止日之前實際還剩幾小時」。

拿掉它，是因為那個數字的誠實**取決於整學期都有人維護那張表**。
一份三週後到期的報告顯示「還有 9 小時」，只有在你真的把每一段時間都排進去、
而且排了就會坐下來寫的時候才成立；否則它是一個看起來很精確的謊。
**過期的數字比沒有數字更糟**——沒有數字時你會自己判斷，有數字時你會相信它。

於是：

- **行事曆上排的都是真的會發生的事**（正課、分組討論），類型少一種
- **作業卡片只講截止日與步驟**：「還要 12h」是步驟預估的加總，
  來源就在同一張卡上，不依賴另一張表
- 壓力標籤從「時間夠／時間不夠」改成「快到期」——
  前者是一個測量結果，後者才是現在還算得出來的事
- `workBlocks` 資料表在 DB v7 移除。還原較早的備份時那張表會被直接略過，
  其餘資料照常還原

### 5.8g 版面整理：把不常用的收起來

一個學期是三十列。**每一列上放什麼，要用「一學期會按幾次」來決定**，不是用
「這個動作存不存在」。

- **每一列一顆「⋯」**。以前每一列都掛著紅色的「刪除」和「標記停課」：
  最危險的動作有了最大的視覺重量和最穩定的位置，而停課一學期用得到一兩次，
  卻整整十五週都佔著版面。現在兩者都在選單裡，選單用 Escape 收起來，
  而且**收的時候把這個按鍵吃掉**，不會連外面的對話框一起關掉
- **側邊欄一次只展開一門課**。五門課同時展開是七十幾列，
  找一週要先捲過另外四門。展開下一門，上一門自己收起來
- **數上課的地方說「堂」**。一週可能有正課也有分組討論，
  「還有 29 週沒排」在一個只有十五週的學期裡是說不通的數字
- **每個對話框標題列都有 ✕**。長對話框（課程規定與作業）的「關閉」在三個螢幕以下，
  而人是往上找關閉鈕的
- **工作區**：只有逐字稿沒有音檔時不放一個 `0:00 / 0:00` 的空播放器，改成直說原因，
  也不把第一句標成「正在講的那一句」、不留一顆跟不了播的「跟播」——**沒有播放頭就別假裝有**；
  第一週的「上一週」不是一顆點不動的按鈕，而是一句「這是第一個」；
  進到某一週的工作區時側邊欄自己收起來，離開再回來——
  但**只收自己收的那次**：在工作區裡自己把它拉開，離開時就讓它開著

### 5.8h 學期長度、播放速度、多段錄音、說話者

- **學期長度是兩個日期算出來的**。原本旁邊還有一個自己填的「週數」，
  三個東西可以互相打架——而週次編號、依課表產生整學期，本來就都是從日期量的。
  現在只問開始日與結束日，下面直接寫「共 15 週」。密集課 6 週、暑期班 8 週，
  都只是不同的結束日。
  升級舊資料時，**先讓結束日涵蓋原本說好的週數再拿掉那個欄位**，
  所以沒有一個學期會因為改用日期而縮短；舊備份還原時走同一條規則
- **播放速度 0.75×–2×**，而且**保持音高**。瀏覽器自己的速度選單藏在三層底下、
  換一個檔案就忘記；這裡記在應用設定裡——會用 1.5× 聽課的人每一週都用 1.5×
- **一堂課可以有好幾段錄音**（中場休息、手機沒電重錄、分兩天補課）。
  **每段各自一條時間軸**，不接成一條：把第 2 段的 0:10 說成 52:10，
  等於發明一個它沒有的時間，也等於宣稱兩段是連著錄的
  - 逐字稿上方有段落列可以切換；只有一段時不畫那一排，只留「再加一段錄音」
  - 筆記裡的時間戳帶得動段號：`[[第2段 00:12:30]]`。
    第 1 段仍寫成 `[[00:12:30]]`——那是既有筆記的格式，也是最常見的情形
  - 重新轉錄、換音檔、刪除都只作用在**你正在看的那一段**
  - 搜尋結果帶著它來自哪一段，點進去會開對的那一段
  - 課程頁分得出「兩段都轉好」與「1 / 2 段已轉錄」
  - 匯出時每一段一個小標，沒轉錄的那段也寫出來，而不是安靜地漏掉
  - 「段」從此是錄音的單位，所以逐字稿的行數改稱「句」——
    同一個畫面上兩件事不能共用一個字
- **逐字稿真的選得起來**。時間欄與說話者名字原本標成 `user-select: none`
  （免得被一起複製走），但**選取不能在這種元素裡開始**——而一行的最左邊、
  正是由左往右拖曳的起點。結果是：從最自然的位置拖，什麼都選不到，
  然後「引用到筆記」只會回一句「請先選取」。
  改成兩者都可選，要不要引用改在事後過濾（`selectedText` 把時間與名字剔掉）。
  另外：**拖曳結束在某一行上不再等於點了它**——那會開始播放並把清單捲走，
  剛選好的字就跑掉了；單擊照樣跳到那一句。
  成功時也回報一句（「已引用到筆記：…」），提示則講清楚該怎麼做
- **逐字稿的工具列收成三顆＋一個「⋯」**。加上標記說話者與只看某人之後，
  那一排有八個控制項，把左邊的標題擠成一行一個字的直排。
  常用的（引用到筆記、選取加入詞彙表、只看某人）留在外面，
  修正錯字、標記說話者、跟播、重轉／換音檔／刪除收進選單；
  **正在某個模式裡時，出口留在外面**（「完成編輯」「標完了」）——
  進去的路可以收起來，出來的路不行
- **說話者是手動標的**。轉錄服務不會分辨說話者：OpenAI 相容的
  `/audio/transcriptions` 根本沒有這個輸出，要自動分辨得換一家會 diarization 的服務、
  另一組金鑰、而且音檔要整份送出去。所以這裡做成**便宜的手工**：
  - 標記只放在**換人講的那一句**，往下沿用到下一個標記——
    一堂課是老師講四十分鐘，每一句都記一次等於同一件事抄四十遍
  - **停頓的地方先幫你標出來**（間隔 ≥ 1.5 秒），三小時的課是點幾下而不是兩百下
  - 名字記在課上，下週不必再打一次；可以「只看某個人講的」
  - 匯出時在換人的那一句前面加上 `**老師：**`

### 5.8i 一套配色

**只有淺色**。原本跟著作業系統走：一份深色色票、幾個 `@media (prefers-color-scheme: dark)`
的例外，還有兩個顏色要各寫一次。兩套配色等於每一個畫面都有兩種樣子要顧，
而其中一種平常沒有人看——包括我自己在做的時候。

- 深色色票與那幾條例外都拿掉了
- `color-scheme: light` 寫在 `:root` 與 `index.html` 兩處。
  **不只是自己畫的部分**：日期與時間選單、下拉、音檔播放器、捲軸是瀏覽器自己畫的，
  沒有這一行的話，作業系統設成深色時它們會是深灰的，貼在一張淺色的頁面上
- 筆記的文字顏色仍然對映回配色 token，理由從「深色主題下看不見」
  改成「那五個顏色就是這一頁在用的五個顏色」

### 5.9 儲存與備份

- **主要模式：本機資料夾**（File System Access API，Chrome）。音檔與 PDF 直接存硬碟，資料庫只存索引與文字。
- **匯出 Markdown**：寫成 `學期/課程/…` 的資料夾樹到你指定的資料夾——
  指向 Obsidian vault，筆記就直接在那裡了。
  每週一個檔，帶 YAML front matter、你的筆記、每行前綴 `` `[hh:mm:ss]` `` 的逐字稿；
  另有課程總表、作業與閱讀材料三份索引
- **備份**：單一 JSON 檔，含全部結構、逐字稿、筆記、修正紀錄與**全域詞彙**，
  可匯入還原、可換電腦。
  **不含音檔**——音檔本來就在你選的資料夾裡，那就是它自己的備份；
  也**不含 API key 與用量**，那兩樣屬於這台機器，還原到別台只會顯示不存在的用量。
  全域詞彙原本和金鑰同住一列，於是跟著被排除——那是一份手工累積的
  人名與原文音譯，正是備份存在的理由，所以單獨帶一個欄位過去
- 「轉錄完成後自動刪除音檔」選項——但預設**保留**，因為時間戳跳轉需要音檔
- API key 存本機 IndexedDB（已確認不需加密）

每個階段結束都是能實際拿去上課用的狀態。

## 7. 技術選型

| 層 | 選擇 | 理由 |
|---|---|---|
| 框架 | Vite + React + TypeScript | 靜態輸出、生態成熟 |
| 資料庫 | Dexie（IndexedDB 封裝） | local-first 標準解 |
| 檔案 | File System Access API | 4.5 GB／學期，非用不可 |
| 音訊處理 | `ffmpeg.wasm` | 壓縮與切片全在瀏覽器完成，不外傳 |
| STT | Groq `whisper-large-v3`（OpenAI 相容端點） | 準確度／價格最佳解，OpenAI 作備援 |
| PDF | `pdf.js`（釘在 5.4.x） | 檢視 ＋ 抽文字。5.5 起用到現行 Chromium 沒有的 API，升版會靜默顯示空白頁 |
| 編輯器 | CodeMirror 6 | Markdown ＋ 可點擊的 `[[hh:mm:ss]]` 裝飾 |
| 全文搜尋 | 直接子字串比對 | 中文沒有空白，詞元索引反而搜不到你記得的那句話 |
| 部署 | GitHub Pages 靜態站 | 零成本、零維運 |
